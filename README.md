# Grunions Water Polo team app
Flask + SQLite. Dark, mobile-first. Runs locally or on Render/any Docker host (see Deploy).

## Run
    ./run.sh    # reads .env.local (BOT_API_KEY, SECRET_KEY, ADMIN_EMAIL, optional VERIFY_WEBHOOK_URL); port 5055
or:
    python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
    ADMIN_EMAIL=you@yourmail.com SECRET_KEY=$(openssl rand -hex 32) .venv/bin/python app.py   # http://localhost:5055
Env: PUBLIC_URL (base URL for QR + login links), EXPIRING_DAYS (default 30), CRON_KEY (lets a scheduler call /api/expiring?key=...),
DEV_SHOW_LINKS=1 (local testing only: show magic link on screen; default 0), SECURE_COOKIES=1 (behind HTTPS), GRUNIONS_DB, PORT.
Demo data: `rm grunions.db && .venv/bin/python seed_demo.py` (admin eli@example.com, coach marcus@example.com).
Tests: `.venv/bin/python test_app.py` (295 checks) and `.venv/bin/python -m pytest -q test_v2.py` (16 tests), `.venv/bin/python -m pytest -q test_google.py` (10 tests). Run each in its own process, or just `./run_tests.sh`. Daily job: `.venv/bin/python daily_expiry.py [--days 30] [--remind]`.

## Roles
member (athlete), active coach (check-in + #coaches), admin (People and the rest of admin). Manage on Admin → **People** (/members), with segments Members, Coaches, Admins, and Referees. The Roles tab is gone. Only admins can open People. The last admin can't remove themselves.
Make admin and Make coach work for any member, whether or not USA Water Polo has verified them. Remove admin and Remove coach take that access away. On Members, a colored dot for the USAWP status (green, amber, red, or gray) sits in front of the name, and the ⋯ menu is at the far right of the row. Tap the row to open the same detail panel as check-in: membership, member number and expiry, trial, SafeSport, background screening, eligibility, who verified them, the bot note, a preferred first name, and Recheck membership. Background screening is required only for an active coach. An admin who is not an active coach does not need it, and a player never does. Recheck membership is manual: the admin enters what they found on Sport:80 (verified yes or no, membership type, membership expiry, and the SafeSport, background screening, and referee certification expiries). Saving records verified by that admin and the Pacific time, recomputes Coach eligible and Referee eligible, and adds a Coach membership to the coaching list without granting coach access. The same form answers a pending verification request. Next to that form, Ask Grunions to verify creates a bot request and sends the webhook, including when the member is already verified. On Members, the ⋯ menu offers Make admin or Remove admin, Add to coaches or Remove from coaches, and Add to referees or Remove from referees. Each change shows a short confirmation. The last admin cannot remove their own admin role. Coach access (check-in and coaches chat) comes only from Make active coach. The coaching list is who can be assigned to a practice. Make active coach does not add someone to that list, and being on the list does not open check-in or coaches chat. Admins are not on that list unless someone adds them. A verified USAWP membership type with the word coach (for example Individual Membership, Coach) adds that person to the coaching list automatically. Edit practice offers a Coaches checkbox for each person on that list. People shows Active coach, Coach for the coaching list, and Coach eligible. Coach eligible is a verified coach membership with current background screening and SafeSport.
Coach eligible is separate from those roles. It shows when a USAWP coach membership is verified and both background screening and SafeSport are current, including on the expiry date itself. The badge is on the member's home card, People (the Coaches segment, including a Coach eligible section for people not on the list yet), the practice coach picker, the practice page, check-in, the members CSV, and the Practices and Practice Coaches sheet tabs. If one of those dates has passed, the line is Coach eligibility expired and that date. A practice with no coach-eligible assigned coach shows that warning to admins on the practice page, and on check-in. Referee eligible uses the same dates for a membership type with the word referee, filled in when a verification result includes that membership and its expiry. The badge is on People (the Referees segment, including a Referee eligible section for people not on the referee list yet), on check-in, and in the Referee eligible column of the members CSV and Members sheet. Add to referees puts someone on that list. A past date reads Referee eligibility expired and that date, and the filter hides that person.
ADMIN_EMAIL (comma-separated) bootstraps admins and keeps them admin on every start; remove an address there to demote it.

Once verified, Edit is hidden and the number stays read-only. Three submissions per member per hour. When that membership date has passed, the line returns to Not cleared for water polo with "Membership expired 2026-10-22" inside the card and a primary Reverify membership button. During the trial the same Membership # form still sends the number for verification and the line shows Verification pending. Once verified, the normal cleared or not-cleared line replaces the trial. Each card matches the Home next-practice card: a date tile, the start time and a short place name, the coaches, a chevron, and the going count. I'm going and I'm not going are equal pills. Tapping a card, anywhere except its buttons, opens /practices/<id>. That page shows the date, time, place, and status, RSVP buttons, the assigned coaches, who's going, who can't make it, who's checked in, a map and a Directions link for the address, and the notes. Admins and active coaches can add an optional after-practice social (Dinner, Drinks, Social, Coffee, Dessert, Activities, Potluck, and Other can be selected together, plus a place, an optional address or map link, an optional time, and a short note). It shows as a line like Drinks after at The Harp, or Dinner & drinks after at The Harp, with the same light-gray cup-and-burger icon in the tile on the Home next practice card and the practice page. Schedule cards do not show the social row. On the practice page it is a section above Coaches. Hosts see Add when it is empty and Edit when it is set; everyone else sees it read-only, and the section is hidden when there is none. An active coach who is not an admin gets only those two menu items. A practice stays on the schedule until its end time, so Friday's 7–8:30 practice is still there after 5pm. A cancellation or a change to the time, place, or note shows a red count on the Schedule tab and a red bubble on that practice until the member opens it. The sheet offers 👍 ❤️ 😂 😮 🎉 🙏 and a few more; reactions already on a message show as small pills underneath, and tapping a pill toggles yours. The composer has an image button and a send icon; announcements already stored still show on Home, and a deleted announcement does not. Only days that have a practice can be selected, and the other days are grayed out. Arrows jump to the previous and next practice. With no date in the link it opens today's practice, or the next upcoming one, in Pacific time. Going lists who RSVP'd and is not checked in yet, A–Z by display name. Everyone else not checked in is the next list, also A–Z. Checked in is a collapsible section at the bottom with a count. Each row keeps its clearance badge. A coach-eligible member shows a Coach eligible badge on check-in, on the member roster, on Roles, in the coach picker, and on that member's home card. If the membership or a screening date has passed, the line is Coach eligibility expired and the date. Check-in shows the assigned coaches, for example Coaches: Eli, Sam, and warns when no assigned coach is coach-eligible. An active 2-week trial shows the days left and end date on check-in and on the member roster; a trial that has ended is marked Trial ended.
  Admin detail panel: open Sport:80 (name copied to clipboard), Recheck membership (verified yes or no, membership type, membership expiry, SafeSport, background screening, and referee certification expiries; records the admin and the Pacific time) with Ask Grunions to verify beside that form, enter compliance items, set role.
- /members (admin, +CSV), /transfer (admin): Sport:80 import at the top, then members CSV and practices/attendance CSV for a start and end date. /import and /export redirect there. Practices is one row per practice (RSVP going, checked-in counts, a Coaches column of display names, and a Coach count). Detailed attendance is one row per member per practice (name, USAWP #, RSVP, checked in, check-in time). Files are UTF-8 with a BOM so Excel opens them, and the filename includes the date or date range. Import accepts Sport:80 .xlsx/.csv including SafeSport/Background columns. Also /qr, /expiring (expired / 7 days / N days, incl. compliance items; in-app reminders), /requirements (configure items, who they apply to, import keywords).
  With GOOGLE_SHEET_ID and GOOGLE_SA_JSON (the full service-account JSON), gspread keeps three tabs: Members (the members CSV columns), Practices (one row per practice), and Attendance (one row per member per practice). A Practice Coaches tab is written too. Changes to a member, a verification result, an RSVP, a check-in, or a practice are synced on a short delay in the background. A full rewrite runs daily at 3:15am Pacific. Admin → Transfer shows Sync to Google Sheet now and the last sync time when those env vars are set; otherwise that card is hidden. A Sheets error is logged and does not break the request.
Status auto-flips to expired once expires_on passes. Cleared to play = USAWP membership verified and current, and SafeSport current, or an active 2-week USAWP trial that is not yet verified. Cleared to coach applies only to an active coach, and it needs a current background screening. An admin who was not made a coach does not need that screening, and a player never does. When a date is on file, the home clearance card and admin member details show a Background screening row like SafeSport training: the label on the left, and a green, amber, or red dot with expires and the date on the right. A coach with no date shows missing. The roster and check-in name lines still read Background screening expires and the date. The members CSV and the Members sheet tab include the date and that line, blank when the member is not a coach and has no date on file. Reminder emails and pushes for a background date go only to coaches. Club waiver is not a requirement.
- /notifications: per-type push toggles, all on until changed. Team chat, coaches chat (coaches and admins), a practice reminder about 3 hours before for anyone who RSVP'd going, verification result, practice cancelled, trial / membership / SafeSport expiring, background screening expiring or expired for coaches, and (admins) new verification requests. Home shows **Allow notifications**. On iPhone or iPad, add Grunions to the Home Screen first (iOS 16.4 or later), then open it from there. Reminder emails (7 days before, 1 day before, and the day it expires) can be turned off here. Practice cancellation emails always send, with the date, time, and location. Each notice is stored so it is not sent twice. An in-process scheduler runs the expiry and reminder checks about every 15 minutes (one scheduler per process, plus a database lock). No extra Render service.
Security: CSRF on every POST and DELETE, HttpOnly SameSite cookies, chat escaped, role checks server-side.
Before production: SMTP configured, DEV_SHOW_LINKS=0, HTTPS, DB backups (copy $DATA_DIR/grunions.db). v1 kept as app_v1_checkin.py.

Templates live in ui.py (restrained dark theme: one surface, gray text, blue only for primary actions and the active tab, status shown as a small dot + label).
Tabs: Home, Schedule, Chat, plus Admin (Check-in for active coaches, and for admins People · Transfer · Expiring · Rules · QR). The bar is the same markup on every page, 64px tall, with inline icons. ## Verification bot API
- Home form or admin "Ask Grunions to verify" creates a verify_requests row (pending). The Home form, if one is already pending, updates that row's member_number instead of inserting another. Admin "Ask Grunions to verify" does not create a duplicate while one is pending.
- Whenever a verify request is created, if VERIFY_WEBHOOK_URL is set, POSTs this JSON (5 s timeout). Failures are logged only and never break the page. A member submitting their own number from Home still sends it.
  `{"request_id": 12, "member_id": 4, "name": "Ana Lopez", "preferred_first": "Ana", "email": "ana@example.com", "member_number": "5555555", "requested_by": "Eli Joern", "member_submitted": false, "app_url": "https://grunions.example"}`
  `requested_by` is the name of the person who asked (the admin, or the member when they submit it themselves). `member_submitted` is true only when that member submitted the request. `app_url` is PUBLIC_URL. `member_number` and `requested_by` are stored on the request. If VERIFY_WEBHOOK_KEY is set, the POST sends `Authorization: Bearer <key>`. If VERIFY_WEBHOOK_HEADER is set, that name is used instead and the value is the raw key (no Bearer prefix).
- Auth: `Authorization: Bearer $BOT_API_KEY` (401 otherwise; API disabled if unset).
- GET /api/verify-requests?status=pending|done → list.
- POST /api/verify-requests/<id>/result  {"verified":true,"member_number":"123","membership_expires_on":"2027-08-31",
  "membership_type":"Individual Membership, Coach","compliance":{"SafeSport training":"2027-05-01"},"note":"..."} → updates member + compliance (matched by requirement name or keyword),
  marks done (409 if already answered) and posts an in-app notice to every admin. It does not post to chat. The member's card updates, and they get the verification-result push when that notification is on.
  When verified is true and membership_type contains the word coach, the member is added to the coaching list. That does not grant coach access. A verified result whose membership type is not a coach membership removes only a USAWP-sourced list row. A failed result, or a result with no membership_type, leaves the list unchanged. Mark membership verified does not set a membership type and does not change the list.

## Deploy (Render)
`render.yaml` defines a Docker web service (gunicorn, 1 worker x 8 threads since SQLite) with a 1 GB persistent disk at `/data` (`DATA_DIR=/data`).
New → Blueprint → point at the repo, then fill PUBLIC_URL and the SMTP_* values. Other hosts: `docker build -t grunions . && docker run -p 10000:10000 -v grunions-data:/data --env-file prod.env grunions`.
Without Docker: `gunicorn app:app --bind 0.0.0.0:$PORT --workers 1 --threads 8`.

## Sport:80 roster import columns
Transfer import takes .csv or .xlsx (title rows above the header are skipped; headers matched case/space/punctuation-insensitively):
- **First Name / Last Name** (or Name / Full Name), **Email / Email Address** — matching (email first, then unique legal first+last). Optional **Preferred First Name / Nickname** is stored as the name shown in the app and is not used to match.
- **ID Number / Member Number / Membership Number** — stored as USAWP #. **Contact ID** — stored as sport80_contact_id.
- **Status / Membership Status** and **Valid Until / Expiry Date / Membership Expiry Date** — status. If there's no status column, a future expiry counts as current.
- **Membership Type / Member Type** — stored on the member. A value with the word coach (not coaches or coaching) adds them to the coaching list. Any other value removes only a USAWP-sourced list row.
- Any column containing a requirement keyword (safesport, background, concussion; editable in Rules) plus expiry/valid through/completed/status updates that item. A Club waiver column is ignored.
A file needs a name or email column plus at least one of status, member number, or expiry.

## Sign in with Google
OpenID Connect via Authlib (state + nonce, ID token checked). Requires `email_verified`. Signs in only when that Google email matches an existing member who registered at /join (case-insensitive). It does not create an account. If there is no registration, the login page says so and offers a Sign up button to /join. An existing admin with that email still signs in, including one created outside /join. Admin is never granted by Google sign-in, only via ADMIN_EMAIL or People.
Redirect URI: `PUBLIC_URL + /auth/google/callback`, e.g. `https://grunions-team-app.onrender.com/auth/google/callback`
(locally without PUBLIC_URL: `http://localhost:5055/auth/google/callback`).

Google Cloud Console setup:
1. https://console.cloud.google.com → project picker → **New project** (e.g. "Grunions") → select it.
2. **APIs & Services → OAuth consent screen** (Google Auth Platform → Branding/Audience): User type **External** → app name "Grunions Water Polo", support email, developer contact email → Save.
   Scopes: add `openid`, `.../auth/userinfo.email`, `.../auth/userinfo.profile` (non-sensitive, no verification review needed).
3. **Audience → Publish app** (move from Testing to **In production**) so any Google account can sign in. In Testing, only listed test users can.
4. **APIs & Services → Credentials → Create credentials → OAuth client ID** → Application type **Web application**, name "Grunions web".
   - Authorized JavaScript origins: `https://YOUR-DOMAIN` (and `http://localhost:5055` for local testing).
   - Authorized redirect URIs: `https://YOUR-DOMAIN/auth/google/callback` (and `http://localhost:5055/auth/google/callback`). Must match exactly: scheme, host, no trailing slash.
5. Create → copy the **Client ID** and **Client secret** into GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET (Render dashboard → Environment, or .env.local). Set PUBLIC_URL to the same https origin. Restart.
